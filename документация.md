## 1. Введение и постановка задачи

**Цель проекта:** разработать программу для учета заказов с возможностью отслеживания статуса каждого заказа.

**Требования:**
- Создание, редактирование, удаление заказов
- Отслеживание статусов (Новый → В обработке → Отправлен → Доставлен / Отменен)
- Добавление заметок к заказам
- Просмотр статистики
- Графический интерфейс на Tkinter
- Разделение кода на модули (модель / менеджер / GUI)

## 3. Модуль `order_model.py` — Модель данных

**Назначение:** описывает предметную область — что такое «заказ» и какие у него бывают статусы.

### Ключевые компоненты

#### 3.1. `OrderStatus` (Enum)

Перечисление возможных статусов заказа. Использование `Enum` вместо строк даёт:
- защиту от опечаток;
- автодополнение в IDE;
- итерацию по всем статусам.

```python
from enum import Enum

class OrderStatus(Enum):
    NEW = "Новый"
    PROCESSING = "В обработке"
    SHIPPED = "Отправлен"
    DELIVERED = "Доставлен"
    CANCELLED = "Отменен"
```

#### 3.2. `Order` (класс модели)

Хранит все данные одного заказа и предоставляет методы для работы с ними.

**Атрибуты:**

| Атрибут | Тип | Описание |
|---|---|---|
| `order_id` | int | Уникальный идентификатор |
| `customer_name` | str | Имя клиента |
| `product` | str | Название товара |
| `quantity` | int | Количество |
| `price` | float | Цена за единицу |
| `status` | OrderStatus | Текущий статус |
| `created_date` | datetime | Дата создания |
| `updated_date` | datetime | Дата последнего изменения |
| `notes` | str | Заметки (с временными метками) |

**Методы:**
- `update_status(new_status)` — меняет статус и обновляет `updated_date`
- `add_note(note)` — добавляет заметку с временной меткой
- `get_total_price()` — возвращает `quantity * price`
- `to_dict()` — сериализация в словарь (для экспорта/сохранения)
- `__str__()` — человекочитаемое представление

## 4. Модуль `order_manager.py` — Бизнес-логика

**Назначение:** управляет коллекцией заказов, инкапсулирует всю бизнес-логику.

### Ключевые методы

| Метод | Назначение | Возвращает |
|---|---|---|
| `create_order(...)` | Создание нового заказа | `Order` |
| `get_all_orders()` | Все заказы | `list[Order]` |
| `get_order_by_id(id)` | Поиск по ID | `Order \| None` |
| `update_order_status(id, status)` | Смена статуса | `bool` |
| `delete_order(id)` | Удаление заказа | `bool` |
| `add_order_note(id, note)` | Добавление заметки | `bool` |
| `get_orders_by_status(status)` | Фильтр по статусу | `list[Order]` |
| `get_statistics()` | Сводная статистика | `dict` |

### Особенности реализации

- **Автоинкремент ID:** `next_order_id` гарантирует уникальность
- **Безопасные операции:** методы возвращают `False`, если заказ не найден
- **Статистика:** считает количество по каждому статусу и общую выручку (без учёта отменённых)

## 6. Подробная документация по Tkinter

### 6.1. Иерархия виджетов

Все виджеты Tkinter наследуются от базового класса `Widget`.

```text
                    Widget (базовый)
                         │
    ┌────────────────────┼────────────────────┐
    │                    │                    │
  Frame              Button              Label
    │
    ├── Toplevel (дочернее окно)
    ├── Tk (главное окно приложения)
    ├── LabelFrame (рамка с заголовком)
    └── PanedWindow (панели с разделителем)

    Ввод данных:
    ├── Entry (однострочное поле)
    ├── Text (многострочное поле)
    ├── Listbox (список)
    ├── Checkbutton (флажок)
    ├── Radiobutton (переключатель)
    ├── Scale (ползунок)
    └── Spinbox (поле со стрелками)

    Отображение:
    ├── Label (текст/изображение)
    ├── Canvas (холст для рисования)
    ├── Message (многострочный текст)
    └── Scrollbar (полоса прокрутки)

    Специальные (ttk):
    ├── Treeview (таблица/дерево)
    ├── Notebook (вкладки)
    ├── Progressbar (прогресс-бар)
    └── Combobox (выпадающий список)
```

### 6.2. Менеджеры геометрии

В Tkinter есть **три** менеджера размещения. В проекте используются все три:

#### `pack()` — блочное размещение

```python
widget.pack(side=tk.TOP, fill=tk.X, padx=10, pady=5, expand=True)
```

| Параметр | Описание |
|---|---|
| `side` | `TOP`, `BOTTOM`, `LEFT`, `RIGHT` |
| `fill` | `X`, `Y`, `BOTH`, `NONE` — заполнение |
| `expand` | `True`/`False` — растягиваться при изменении размера |
| `padx/pady` | Внешние отступы |
| `ipadx/ipady` | Внутренние отступы |

#### `grid()` — табличное размещение (используется в форме)

```python
widget.grid(row=0, column=1, sticky=tk.W, padx=5, columnspan=2)
```

| Параметр | Описание |
|---|---|
| `row`, `column` | Индексы ячейки |
| `rowspan`, `columnspan` | Объединение ячеек |
| `sticky` | Прилипание: `N`, `S`, `E`, `W` и их комбинации |
| `padx/pady` | Отступы |

#### `place()` — абсолютное/относительное размещение

```python
widget.place(x=100, y=50, width=200, height=30)
widget.place(relx=0.5, rely=0.5, anchor=tk.CENTER)
```

> 💡 **Правило:** в одном контейнере нельзя смешивать `pack` и `grid` — будет конфликт.

### 6.3. Обработка событий

#### Привязка команд к кнопкам

```python
btn = tk.Button(root, text="Нажми", command=my_function)
```

#### Привязка событий через `bind()`

```python
widget.bind("<Button-1>", on_click)        # ЛКМ
widget.bind("<Key>", on_key)               # Любая клавиша
widget.bind("<Return>", on_enter)          # Enter
widget.bind("<Control-s>", on_save)        # Ctrl+S
widget.bind("<Double-Button-1>", on_dbl)   # Двойной клик
```

#### Передача аргументов в обработчик

```python
# Через lambda
btn.config(command=lambda: do_something(arg1, arg2))

# Через functools.partial
from functools import partial
btn.config(command=partial(do_something, arg1))
```

### 6.4. Диалоговые окна

#### `messagebox` — стандартные диалоги

```python
from tkinter import messagebox

messagebox.showinfo("Заголовок", "Информация")

    ...
if messagebox.askokcancel("Вопрос", "Продолжить?"):
    ...

# Возвращает True / False / None
```

#### `simpledialog` — диалоги ввода

```python
from tkinter import simpledialog

name = simpledialog.askstring("Имя", "Введите имя:", parent=root)
```

#### `filedialog` — выбор файлов

```python
from tkinter import filedialog

    filetypes=[("Text files", "*.txt"), ("All files", "*.*")]

filename = filedialog.asksaveasfilename(defaultextension=".txt")

```

#### Создание дочернего окна (`Toplevel`)

```python
win = tk.Toplevel(parent)
```

#### 📝 Правила хороших коммитов:

✅ **Атомарность:** один коммит = одна логическая единица работы
✅ **Осмысленные сообщения:** используйте conventional commits
✅ **Частота:** коммитьте каждые 30-60 минут работы
✅ **Рабочее состояние:** коммит должен компилироваться/запускаться
❌ **НЕ коммитьте:** временные файлы, секреты, большие бинарники

#### Формат сообщений коммитов (Conventional Commits):

```text
<type>(<scope>): <description>

[optional body]

[optional footer]
```

**Типы:**
- `feat` — новая функциональность
- `fix` — исправление ошибки
- `docs` — изменения в документации
- `style` — форматирование, отступы (без изменения кода)
- `refactor` — рефакторинг без изменения функциональности
- `test` — добавление тестов
- `chore` — рутинные задачи (обновление зависимостей и т.п.)

**Примеры:**

```bash
git commit -m "feat(model): Add OrderStatus enum with 5 states"
git commit -m "fix(gui): Fix validation for negative prices"
git commit -m "docs: Update README with installation instructions"
git commit -m "refactor(manager): Extract validation logic to separate method"
```
